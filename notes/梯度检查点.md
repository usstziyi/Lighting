def forward(self, x):
    # 使用梯度检查点节省显存
    if self.hparams.use_gradient_checkpointing and self.training:
        return torch.utils.checkpoint.checkpoint(self.net, x, use_reentrant=False)
    return self.net(x)

## 原理（为什么要这么做）

正常训练时，反向传播需要用到**前向过程中的中间激活值**（每层的输出），所以 PyTorch 会把它们全部存在显存里。网络越深/batch 越大，中间结果越多，显存越吃紧。

梯度检查点的做法是：**前向时不保存中间激活**，只保留输入和网络本身；等到反向传播需要某个中间值时，**重新前向计算一遍**把它算出来。

## 权衡

| | 显存 | 计算量 |
|---|---|---|
| 普通训练 | 高（存所有中间激活） | 低 |
| 梯度检查点 | 低（几乎只剩参数 + 少量缓存） | 高（多一次前向重算，约多 20%~40% 时间） |

## 结论

- **适合**：大模型/大 batch 训练时显存不够用的情况
- **不适合**：这个 demo 里的小网络（几个 Linear 层），显存完全够，开了反而白费计算
