**True Positive（真正例 / 真阳性）**

即"预测为正例（Positive），且实际确实为正例（True）"——猜对了的"正"样本。

对应另外三个混淆矩阵成员：

| 缩写 | 全称 | 中文 |
|---|---|---|
| **tp** | True Positive | 真正例 |
| **fp** | False Positive | 假正例（误报） |
| **fn** | False Negative | 假负例（漏报） |
| **tn** | False Negative → **True Negative** | 真负例 |

命名逻辑：第一个词 `True/False` 表示"猜对/猜错"，第二个词 `Positive/Negative` 表示"判成了正例/负例"。

- **tp** = 判成正例，且判对了
- **fp** = 判成正例，但判错了（误报）
- **fn** = 判成负例，但判错了（漏报）
- **tn** = 判成负例，且判对了


好，用**男生找对象**来诠释——先定好设定：

> **正例（Positive）= 合适的人**（心动、值得追），**负例（Negative）= 不合适的人**（不来电）。
> "预测为正" = 心动并出手追求，"预测为负" = 无感不追。

## 四类指标对照表

| 指标 | 全称 | 找对象的场景 | 结果 |
|---|---|---|---|
| **TP** | True Positive 真喜欢 | 遇到**合适的人**，一眼心动，出手追到 | 收获爱情 ✓ |
| **FP** | False Positive 假喜欢 | 遇到**不合适的人**，误判为心动，追了才发现不对 | 错付感情 ✗ |
| **FN** | False Negative 假讨厌 | 遇到**合适的人**，却没心动没行动，眼睁睁错过 | 遗憾错过 ✗ |
| **TN** | True Negative 真讨厌 | 遇到**不合适的人**，无感不追，各自安好 | 正确跳过 ✓ |

记忆口诀：**TP/FN 说的是"合适的人"**（追对了 vs 错过了），**FP/TN 说的是"不合适的人"**（错追了 vs 正确跳过）。

## 对应到代码里的指标

[L95-L97](file:///Users/usst_ziyi/Programs/trae/DeepL/Lighting/lessons/lesson_04_logging.py#L95-L97) 的两个指标用这个场景解释非常形象：

- **Precision = tp/(tp+fp)** = 追过的人里，多少是真喜欢 -> 精确率
- **Recall = tp/(tp+fn)** = 真喜欢的人里，多少被追到了 -> 召回率
- **F1** = 两者调和平均 = **追得准 vs 追得全**的平衡

这正好对应恋爱中的两种常见策略：

- **广撒网型**（recall 高）：每个稍微心动的都追 → 不容易错过，但 fp 高，经常错付
- **宁缺毋滥型**（precision 高）：只追确定合适的 → 不浪费感情，但可能 fn 高，错过真爱

## 一个具体例子

假设他见过 6 个人，其中 2 个是合适的（cls）：

```
真实（是否合适）: [合适, 合适, 不合适, 不合适, 合适, 不合适]
心动并出手:       [  追,  不追,   追,    不追,   追,    不追]

tp = 2（第1、5位：合适且追了）→ 追对
fp = 1（第3位：不合适却追了）→ 错付
fn = 1（第2位：合适却没追）  → 错过
tn = 2（第4、6位：不合适也没追）→ 正确跳过

precision = 2/3 ≈ 0.67  追的人里 67% 是合适的
recall    = 2/3 ≈ 0.67  合适的人里追到了 67%
```

> 小提示：这个比喻和警察抓小偷本质相同，只是**正例/负例的"代价"不同**——找对象场景里 FP（错付）和 FN（错过）的痛感不一样，这恰好说明为什么不能只看 Accuracy，而要结合 Precision/Recall 看。


它们的关系是：**Precision 和 Recall 是两个互相独立的"单视角"指标，F1 是把它们压缩成一个数的"综合指标"。**

## 三个公式

[L95-L101](file:///Users/usst_ziyi/Programs/trae/DeepL/Lighting/lessons/lesson_04_logging.py#L95-L101)：

```python
precision = tp / (tp + fp)                    # 查准：追的人里多少合适
recall    = tp / (tp + fn)                    # 查全：合适的人里追了多少
f1        = 2 * precision * recall / (precision + recall)   # 调和平均
```

## 核心区别：分母不同，问的问题不同

| 指标 | 公式分母 | 问的问题 | 找对象场景 |
|---|---|---|---|
| **Precision** | tp + fp（所有"预测为正"的） | 我"出手"的对不对？ | 追过的人里，几个是真合适？ |
| **Recall** | tp + fn（所有"真实为正"的） | 我"漏掉"的多不多？ | 合适的人里，我追到了几个？ |
| **F1** | 两者综合 | 追得"又准又全"吗？ | 前面两个问题的平衡分 |

## 为什么不能只看一个？

两者经常此消彼长，而且**只看一个会骗人**：

| 策略 | Precision | Recall | 问题 |
|---|---|---|---|
| 只追百分百确定的 | 高（1.0） | 低（0.05） | 几乎不追 → 错过所有机会 |
| 见谁都追 | 低（0.1） | 高（1.0） | 全追了，但错付一堆 |

只看 Precision 会以为"我很挑很准"，其实是在逃避；只看 Recall 会以为"我很主动"，其实在乱追。**F1 就是要惩罚这种"偏科"**。

## 为什么 F1 用调和平均，而不是算术平均？

这是 F1 的关键设计。算术平均（`(P+R)/2`）会让偏科显得还行：

```
precision = 1.0, recall = 0.01

算术平均 = (1.0 + 0.01)/2 = 0.505   ← 看起来还挺好？其实错过了一切
调和平均 = 2·1.0·0.01/(1.0+0.01) ≈ 0.02  ← 诚实地给出低分
```

**调和平均对"两项都很高"极其苛刻**：任何一个接近 0，F1 就接近 0。只有两个都高，F1 才高——这正是我们想要的"不准偏科"。

等价写法更直观：`F1 = 2/(1/P + 1/R)`，即"两个数的倒数的平均的倒数"，数值上**永远小于等于算术平均**。

## 一句话总结

```
Precision = 追得准不准（怕错付）
Recall    = 追得全不全（怕错过）
F1        = 两者的平衡分（偏科就扣分，两个都好才高分）
```

实践中：**怕误报（如垃圾邮件误删）→ 更看 Precision；怕漏报（如癌症筛查）→ 更看 Recall；两者都重要 → 看 F1。**
